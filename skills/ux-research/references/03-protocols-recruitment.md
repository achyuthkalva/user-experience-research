# 03 — Prepare neutral instruments and recruit the right people

**Source basis:** Playbook v1.2, Parts 5–8 and Appendix A.2, A.6–A.10. Safeguards and contextual qualifications are logged in 10.

## Define the population before selecting the convenient sample

Identify roles, relevant experience, behaviours, contexts, access needs, and meaningful segments. Add demographic criteria only when they matter to the research question. A documented target-user definition is enough; do not require invented personas before research can begin.

Choose among client-assisted recruitment, a third-party recruiter/panel, live intercepts, existing user lists, relevant communities, field/intercept recruitment, and carefully labelled convenience sources. Record likely exclusions, incentives, access restrictions, and independence risks. Friends and colleagues are not automatically target users. Employees and researchers can be valid participants when they genuinely belong to the target population; record relationships and bias risks.

Keep the contact list separate from analytical evidence. Use project-scoped pseudonymous IDs. For repeat sessions, preserve the same participant ID with distinct session IDs.

## Create a screener that qualifies without coaching

Capture only necessary eligibility and logistics. Put efficient qualifying items early. Use concrete recent experiences, clearly bounded time periods, non-overlapping options, and appropriate “other,” “none,” “not applicable,” or “prefer not to say” choices. Avoid revealing the desired qualifying answer.

Keep it as short as the eligibility decision allows; the source's 5–6 item target is a starting point, not a forced ceiling. Open text can help distinguish genuine experience but should not become an unnecessary writing test. Yes/no is appropriate for genuine binary facts or explicit consent; it is weak as the sole test of nuanced experience. Use plausible non-qualifying choices where relevant, not confusing traps or inaccessible attention tests.

For each item document: RQ/eligibility purpose, exact wording, response options, accept/conditional/reject logic, and rationale. Never show internal selection labels to applicants. Pilot the wording and routing. Use a truthful rejection message; do not promise future contact unless planned and permitted.

## Build the instrument for the selected method

| Method | Required protocol components |
| :--- | :--- |
| Interview | RQ map; broad-to-specific topics; recent-event questions; neutral probes; optional branches; timing; consent and close |
| Moderated usability | Realistic task scenarios; observation plan; success/failure/assisted definitions; neutral prompts; assistance thresholds; recording permissions |
| Unmoderated study | Clear independent instructions; supported task state; task order; outcome instrumentation; appropriate follow-up; pilot and quality exclusions |
| Survey | Constructs; items and response options; routing/order; sampling; accessibility; pilot; analysis and missing-response rules |
| Analytics/funnel | Event definitions; entry population; inclusion/exclusion; identity/session rules; time windows; instrumentation QA; metric denominator |
| Experiment | Hypothesis; variants; assignment unit; outcomes; guardrails; sample/duration; stopping/decision rules; analysis and exclusions |
| Secondary-evidence review | Source universe; search/access plan; inclusion/exclusion; extraction fields; coding scheme; deduplication; relevance/quality judgement |
| Card sort/tree test | Card labels/tree; task instructions; ordering/randomisation where appropriate; audience; outcomes; analysis plan |

## Use the nine-element structure for moderated usability

1. **Introduction:** explain the researcher role without implying a correct answer.
2. **Goal:** explain what is being evaluated; the participant is not being tested.
3. **Rules:** describe the session and demonstrate think-aloud when the design uses it.
4. **Comfort:** check access needs, equipment, language, questions, and breaks.
5. **Recording permission:** confirm the approved consent process before recording. Do not imply that a generic script guarantees legal compliance.
6. **General questions:** begin with context and recent experience, not product-leading questions.
7. **Contextual tasks:** supply a realistic goal and necessary constraints without naming the intended navigation or control.
8. **Observe and probe:** record what happens; ask neutral follow-ups without teaching the solution.
9. **Close:** invite final comments, restate data use/withdrawal contact, explain any agreed compensation, and complete the secure handoff.

Element order is a guide, not a reason to collect personal data before consent. Where an introductory conversation is recorded or documented as research, obtain the relevant consent first.

### Question-crafting checks

| Risky prompt | Better approach |
| :--- | :--- |
| “How much time does this save?” | “What changes, if anything, when you use it?” |
| “Why was that frustrating?” | “How was that experience for you?” |
| “Click the filter to find a course.” | “Find an option that meets these needs.” |
| Participant says “rectangle”; moderator says “button.” | Mirror “rectangle” until the participant's own meaning is understood. |
| “Great, that is what we hoped!” | Use a neutral acknowledgement, then continue. |
| “Would you use this every day?” | Ask about the last relevant situation, constraints, and alternatives; do not treat predicted use as observed demand. |

### Branch deliberately and mark contamination

If the participant hesitates, allow space, then ask what they are considering. If they ask what to click, ask what they would normally try. When a predefined stop/assistance threshold is reached, record the unaided outcome before giving a neutral rescue prompt. Mark all later behaviour as assisted where relevant. Do not count eventual completion as unaided success.

For a missed element, observe first. A later directed probe can test comprehension, but cannot retroactively prove that the element was naturally discoverable. For distress, confusion about consent, or a request to stop, pause immediately and follow the approved process.

Use silence to provide room to think, not to create discomfort or pressure disclosure. Keep the participant comfortable. Think-aloud is a technique for relevant designs, not the only possible data in unmoderated research. Performance logs, outcomes, timings, or other measures may also be collected; choose and document the design. See E8 and E9 in 10.

## Run the minimum readiness review

Check item-to-RQ coverage, realistic tasks, non-leading wording, balanced response options, valid selection criteria, consent/data handling, accessibility, technical reliability, assistance definitions, timing, and deviation logging. Use a peer, cultural/domain reviewer, or analyst where the risk warrants it. Pilot the instrument and record corrections.

Do not send invitations, schedule participants, or launch a survey merely because you drafted the materials. These are external actions requiring the user's explicit request, necessary details, and appropriate tool permissions.
